# aalint 2.4.1-test1 测试说明

此版本的目标不是自行实现 aardio parser，而是让 aalint 更接近 aardio IDE/运行时的验证环境：

- 语法真值仍由 aardio 内核 `loadcode()` 提供。
- 检查/运行时按 `.aproj` 自动解析 AppRoot；可用 `--root` 强制指定。
- UI flow 增加等待、存在性断言、后台按钮点击与关闭动作，重点覆盖“语法通过、点击按钮后才报错”的场景。
- `global.onError(err,over)` 在错误栈尚未展开时记录 traceback，用来捕获 UI 事件回调里的未处理错误。
- capture 增加 `console.writeText` 拦截，并完整恢复 `console.log/print/write/writeText` 与全局 `print`。
- lint 使用跨行 aardio 字符串/块文本遮罩；已确认与 aardio 语义冲突的旧规则默认禁用。
- `contains` 明确按字面包含处理，不再误用 aardio pattern。
- `--imports` 使用 AppRoot 下的 `lib`，并忽略字符串/注释文本里的伪 `import`。

## 建议测试

```batch
:: 1. 普通语法检查（子目录文件也应使用工程根目录作为 AppRoot）
aalint.exe path\to\project\src\test.aardio

:: 2. 显式指定 AppRoot
aalint.exe --root D:\project D:\project\src\test.aardio

:: 3. UI flow：点击按钮后如回调报错，应返回 runtime FAIL + traceback
aalint.exe --run --timeout 5 --ui-flow docs\ui-flow.example.json D:\project\main.aardio

:: 4. 隔离 UI flow：原生崩溃/后台线程场景优先使用
aalint.exe --run-isolated --timeout 8 --ui-flow flow.json D:\project\main.aardio

:: 5. 保守 lint / 实验 lint
aalint.exe --lint file.aardio
aalint.exe --lint-all --lint file.aardio
```

## 当前仍保留的限制

- `--ui-flow` 目前基于 Win32 子窗口枚举；plus/custom/web 内部控件不一定都有独立 HWND。
- `--ui-smoke` 属于粗粒度烟测，真实业务流程优先写 `--ui-flow`。
- `--lib` 会涉及 aardio `fiber.create(..., appBaseDir)` 同时改变 AppRoot 与用户库目录的语义，本测试版没有对这部分做激进重构。
- snapshot 注入仍以 `win.loopMessage();` 为默认插入点；复杂源码建议优先使用明确的测试入口/flow。
